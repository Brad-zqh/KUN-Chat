# KUN Chat 账号、积分与充值方案

## 目标

参考 `fengge.chat` 的交互方式，为公开部署的 KUN Chat 增加注册登录、积分余额、使用扣费与 Stripe Checkout。积分和支付结果必须由服务端确认，不能以 `localStorage` 为准。

## 第一版账户流程

- 注册：手机号、短信验证码、密码、确认密码。
- 登录：手机号和密码；提供找回密码。
- 密码：仅保存 Argon2id 哈希，不记录明文。
- 会话：使用 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie；会话可撤销并设置过期时间。
- 短信：接入正规短信服务商；验证码做哈希、短时过期、频率限制和失败次数限制。

若暂时不接短信，可先使用邮箱验证码或魔法链接作为成本更低的内测方案，但不能把浏览器本地数据当正式账户。

## 服务端数据

- `users`：用户、手机号/邮箱、密码哈希、状态与创建时间。
- `sessions`：会话摘要、用户、过期时间、撤销时间。
- `credit_ledger`：每一次充值、消费、退款或人工调整；余额由账本汇总或事务内更新。
- `checkout_orders`：套餐、金额、币种、Stripe Checkout Session、支付状态。
- `usage_events`：文字模型和语音合成的真实用量、扣费规则、幂等键。
- `webhook_events`：Stripe 事件 ID，用于验签、去重和重放保护。

本地单机可用 SQLite；公开部署建议 PostgreSQL。所有余额变更都必须放在数据库事务中，避免重复扣费或重复到账。

## Stripe 流程

1. 浏览器请求服务端创建 Checkout Session，不接受浏览器自行提交的价格。
2. 服务端从套餐表读取金额与积分，创建 Stripe Checkout。
3. 用户在 Stripe 托管页使用可用的支付宝或银行卡方式付款。
4. 只有验签成功的 `checkout.session.completed` webhook 才能把积分写入账本。
5. `success_url` 只负责展示“正在确认”；不能仅凭跳转参数判定到账。
6. webhook 事件 ID、订单 ID 和账本幂等键均设唯一约束。

文字与语音不要直接写死为永久价格。建议在服务端维护版本化计价规则，并记录每次消费对应的规则版本。语音成本受字数、模型和生成时长影响，可先预扣、失败全额返还，再按最终用量结算。

## 上线前必须配置

- Stripe 商户账号、商品/价格或服务端价格表。
- `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET`，只写入部署环境变量。
- HTTPS 公网域名及 webhook 回调地址。
- 数据库、备份、日志脱敏、限流、退款与客服流程。
- 充值服务条款、隐私说明、AI 身份标识和适用地区的合规检查。

在上述条件未完成前，网页保持免费内测，不放置不可用的充值按钮。
